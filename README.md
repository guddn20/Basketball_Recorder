# 코트 기록실 · COURTSIDE

농구 경기 영상을 보면서 **선수별 득점과 경기 기록을 정리하는 프로그램**입니다. 농구 동호회 영상처럼 사람이 직접 검토할 영상을 대상으로 만든 시험 버전입니다.

프로그램이 사람과 공을 찾아 슛으로 보이는 장면을 제안하면, 사용자가 영상을 확인해 기록을 확정합니다. 확정한 장면은 선수별 기록표인 **박스스코어**에 합산됩니다.

```text
영상 추가 → 선수·골대 지정 → 자동 후보 찾기 → 사람이 확인·확정 → 기록표 저장
```

브라우저에서 사용하지만 영상 분석과 저장은 이 컴퓨터에서 이루어집니다. 별도 회원가입이나 외부 AI 서비스의 API 키는 필요하지 않습니다. **자동 후보가 곧 득점 기록은 아닙니다.**

## 1. 처음 실행하기

### 이미 설치된 이 컴퓨터에서 실행할 때

1. 프로젝트 폴더의 `start.cmd`를 더블클릭합니다. 바탕화면에 **농구 기록실** 바로가기가 있다면 그것으로 실행해도 됩니다.
2. 브라우저에 코트 기록실 화면이 열릴 때까지 기다립니다.
3. **경기 영상 추가**를 눌러 분석할 영상을 선택합니다. 이미 등록된 영상이 있다면 왼쪽 목록에서 선택할 수 있습니다.

실행 오류가 나거나 다른 컴퓨터에서 처음 사용하는 경우에는 아래 설치 과정부터 진행하세요. 저장소를 새로 내려받으면 샘플 영상과 기존 기록은 포함되어 있지 않습니다.

### 처음 설치하는 컴퓨터에서 준비할 때

아래 실행 스크립트는 **Windows와 PowerShell**을 기준으로 작성되어 있습니다.

| 준비물 | 필요한 이유 |
| --- | --- |
| Python | 서버와 영상 분석 코드를 실행합니다. 설치 스크립트는 Python 3.11~3.14의 사용자 기본 설치 경로를 찾습니다. |
| 인터넷 연결 | 처음에 필요한 파이썬 라이브러리와 AI 모델 파일을 내려받습니다. 모델 준비 후 영상 분석은 로컬에서 실행합니다. |
| 농구 영상 파일 | 직접 준비합니다. 파일당 최대 8GB이며, MP4(H.264) 형식을 권장합니다. |
| 저장 공간 | 원본 영상의 복사본, 분석 결과, 파이썬 실행 환경과 모델을 저장합니다. |

1. Python이 없다면 [Python 공식 홈페이지](https://www.python.org/downloads/windows/)에서 설치합니다. 자동 설치 스크립트를 사용하려면 사용자 기본 설치 경로를 사용하세요.
2. 이 프로젝트를 내려받아 압축을 풀고, `README.md`와 `setup.ps1`이 보이는 폴더를 엽니다.
3. 파일 탐색기의 주소 표시줄에 `powershell`을 입력하고 Enter를 누릅니다. 해당 폴더에서 명령을 입력하는 창이 열립니다.
4. 아래 명령을 복사해 실행합니다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\setup.ps1
```

이 명령은 프로젝트 전용 파이썬 환경인 `.venv`를 만들고, 필요한 라이브러리와 `models/yolo11n.pt` 모델 파일을 준비합니다. 다운로드가 끝나고 `Ready. Double-click start.cmd.`가 나오면 설치 완료입니다.

5. `start.cmd`를 더블클릭합니다. 이후에는 설치 과정을 반복하지 않고 `start.cmd`로 실행하면 됩니다.

## 2. 첫 영상을 기록하는 순서

처음에는 영상 전체보다 **30~60초 정도의 짧은 구간**으로 사용 방법을 익히세요.

1. **영상 추가와 촬영 범위 선택**: **경기 영상 추가**를 누른 뒤, 촬영 범위를 **한 팀 공격 영상 / 득점·하이라이트 모음 / 양 팀 연속 경기 영상** 중에서 고릅니다. 원본 파일은 수정하지 않고 `data` 폴더에 복사합니다. 카메라도 고정 또는 이동 촬영에 맞게 선택합니다.
2. **선수 등록**: 선수가 잘 보이는 장면에서 일시정지하고 **선수 지정**을 누릅니다. 머리부터 신발까지 전신을 드래그한 뒤 이름, 팀, 특징 등을 입력합니다. 등번호는 메모로 저장하며 자동으로 읽지는 않습니다.
3. **같은 선수의 참고 장면 추가**: 앞모습과 뒷모습이 다르다면 **선수 지정 → 연결할 선수 선택**으로 같은 선수에게 장면을 추가합니다. 추가한 장면은 다음 분석부터 반영됩니다.
4. **골대 등록**: **골대 지정**을 누르고 실제 공격 골대의 림(공이 통과하는 링)을 작은 사각형으로 감쌉니다. 림의 가로 폭과 두께를 포함하고, 백보드 전체나 기둥은 포함하지 않습니다. 구도가 바뀌는 영상은 적용 시간 구간을 나눕니다. 같은 시간대에는 공격 골대 하나만 지정합니다.
5. **자동 후보 찾기**: 시작·종료 시간을 입력하고 기본 **5fps**로 **분석 시작**을 누릅니다. 여기서 5fps는 영상의 모든 장면 대신 대략 1초에 5장의 이미지를 골라 분석한다는 뜻입니다. 처리 시간은 영상 길이와 PC 성능에 따라 달라집니다.
6. **장면 확인과 확정**: **확인 필요** 목록에서 장면을 선택해 앞부분부터 재생합니다. 선수, 성공·실패, 자유투·2점·3점을 확인한 뒤 **확정하고 기록**을 누릅니다. 슛 장면이 아니면 **후보 제외**를 누릅니다.
7. **빠진 기록 보완**: **현재 장면 기록** 또는 `M` 키로 놓친 슛을 추가합니다. 리바운드·어시스트·스틸·블록·턴오버·파울도 직접 기록할 수 있습니다. 어시스트는 득점과 별도로 한 번 기록해야 합니다.
8. **결과 저장**: **박스스코어 CSV**로 선수별 기록표를, 장면 목록의 **CSV**로 장면별 기록을 내려받습니다. **기록 백업**은 JSON 형식으로 저장합니다.

선수 이름이 잘못 연결되었다면 **추적 구간** 탭이나 영상 위의 박스를 눌러 수정합니다. 같은 선수도 다른 선수에게 가려지거나 화면 밖으로 나가면 여러 추적 구간으로 나뉠 수 있습니다.

브라우저를 닫아도 저장한 기록은 남습니다. 프로그램의 서버까지 종료하려면 `stop.cmd`를 실행합니다. 분석 중에는 먼저 화면의 **중지**를 누르고 결과 저장이 끝날 때까지 기다리세요. 서버를 바로 종료하면 진행 중인 분석 결과는 저장되지 않습니다.

## 3. 자동으로 해주는 일과 직접 확인할 일

| 작업 | 프로그램의 역할 | 사용자가 할 일 |
| --- | --- | --- |
| 사람·공 찾기 | YOLO11n 모델로 영상 속 사람과 공의 위치를 찾습니다. | 놓친 장면이나 잘못 찾은 대상을 확인합니다. |
| 선수 이름 제안 | 등록한 참고 장면의 상의·하의·신발 색과 비교합니다. 얼굴 인식은 사용하지 않습니다. | 이름 후보를 확인하고 잘못 연결된 추적 구간을 수정합니다. |
| 슛 장면 제안 | 지정한 골대 주변의 공 감지와 주황색 움직임으로 후보를 만듭니다. | 실제 슛인지, 누가 던졌는지, 성공·실패와 점수 구분을 확인합니다. |
| 이동 촬영의 골대 위치 찾기 | 등록한 골대 주변 이미지와 비슷한 부분을 다음 장면에서 찾습니다. | 줌·가림·급격한 이동으로 골대를 놓친 구간을 확인합니다. |
| 기록표 계산 | 사람이 확정한 기록을 합산합니다. | 빠진 기록을 보완하고 결과를 검토합니다. |

등번호 자동 읽기, 농구 전용 선수 재식별 모델, 3점 라인 판정, 자동 어시스트·리바운드·파울 판정, 출전시간 집계는 제공하지 않습니다.

분석은 일부 프레임만 골라 처리하므로 빠른 슛이나 작은 공을 놓칠 수 있습니다. 기본 5fps보다 촘촘하게 확인하려면 10fps를 선택할 수 있지만 정확도를 보장하지는 않습니다. 슛 후보 시간은 보통 공이 골대 부근에 있는 순간이므로 슛을 던지는 앞 장면부터 확인하세요.

## 4. 기록표를 읽을 때 알아둘 점

**모든 숫자는 이 영상에서 확인·확정한 장면의 합계입니다.** 촬영하지 못한 부분까지 포함한 경기 전체의 공식 기록을 뜻하지 않습니다.

| 표시 또는 영상 종류 | 집계 방식 |
| --- | --- |
| 확인 필요·임시 저장 | 박스스코어에 포함하지 않습니다. |
| 확정 | 등록된 선수의 기록으로 합산합니다. 슛은 성공·실패와 점수 구분도 있어야 확정할 수 있습니다. |
| 제외 | 박스스코어에 포함하지 않습니다. |
| `0` | 현재 집계 범위에서 해당 항목으로 합산된 기록이 없습니다. |
| `—` 또는 CSV의 `미집계` | 영상 범위가 부족하거나 시도 횟수가 없어 해당 값을 계산하지 않습니다. 0과 다릅니다. |
| 득점·하이라이트 모음 | 실패 장면이 빠질 수 있으므로 슛 시도 횟수와 성공률을 미집계로 표시합니다. 리바운드 등 부가 기록은 직접 확정한 항목만 표시합니다. |
| 한 팀 공격 영상 | 수비 리바운드·스틸·블록·파울은 기본적으로 미집계이며, 직접 확인해 확정한 항목은 표시합니다. |
| 양 팀 연속 경기 영상 | 확정한 기록으로 시도 횟수와 성공률을 계산합니다. 촬영·분석에서 빠진 장면은 직접 보완해야 합니다. |

예를 들어 등록한 선수가 성공한 2점슛 하나를 **확정**하면 `PTS`는 2, `FGM`은 1, `FGA`는 1이 됩니다. 같은 장면을 3점으로 수정하면 `PTS`는 3으로 다시 계산되며 기록이 하나 더 추가되지는 않습니다. 하이라이트 모드에서는 이 예시의 `FGA`와 성공률을 미집계로 표시합니다.

| 기록표 약어 | 뜻 |
| --- | --- |
| PTS | 득점 |
| FGM / FGA / FG% | 2·3점슛 성공 수 / 시도 수 / 성공률. 자유투는 제외합니다. |
| 3PM / 3PA / 3P% | 3점슛 성공 수 / 시도 수 / 성공률 |
| FTM / FTA / FT% | 자유투 성공 수 / 시도 수 / 성공률 |
| OREB / DREB | 공격 리바운드 / 수비 리바운드 |
| AST / STL / BLK | 어시스트 / 스틸 / 블록 |
| TOV / PF | 턴오버 / 파울 |

같은 시간 구간을 다시 분석하면 그 구간의 기존 자동 **미확정** 후보를 교체합니다. 직접 기록한 이벤트와 이미 확정·제외한 이벤트는 보존합니다.

## 5. 저장 위치와 백업

기본 저장 위치는 프로젝트 안의 `data/<영상 ID>/`입니다. 영상 ID는 프로그램이 영상마다 붙이는 고유한 폴더 이름입니다. 영상과 기록은 외부 서비스로 업로드하지 않습니다.

| 파일 | 내용 |
| --- | --- |
| `video.*` | 추가한 원본 영상의 복사본 |
| `poster.jpg` | 영상의 미리보기 이미지 |
| `session.json` | 선수·참고 장면·골대 구간·장면 기록·확정 상태 |
| `analysis.json` | 분석한 프레임과 선수 추적 구간 |
| `last_error.log` | 분석이 실패했을 때 남기는 오류 정보 |

CSV는 Excel 등에서 열 수 있는 표 파일입니다. 한글이 깨지는 일을 줄이도록 UTF-8 BOM 형식으로 저장합니다. JSON은 선수와 장면 등의 정보를 항목별로 저장하는 텍스트 파일입니다.

영상까지 백업하려면 **분석을 중지하고 서버를 종료한 뒤 프로젝트 폴더 전체를 복사**하세요. 화면에서 내려받는 JSON에는 원본 영상이 포함되지 않으며, 현재 화면에서 JSON을 다시 가져오는 기능도 없습니다.

Git 저장소에는 `data/`, `.venv/`, `models/*.pt`, `test-results/`가 제외되어 있습니다. 새로 내려받은 프로젝트에서는 설치와 모델 준비를 다시 해야 하며, 기존 영상과 기록을 옮기려면 별도로 복사해야 합니다.

## 6. 문제가 생겼을 때

| 증상 | 확인할 내용과 해결 방법 |
| --- | --- |
| `start.cmd` 실행이 실패함 | 먼저 설치 과정을 완료했는지 확인합니다. 오류가 `Python dependencies are missing`이면 `setup.ps1`을 실행하세요. |
| 설치 중 `Install Python` 오류가 나옴 | 자동 설치 스크립트가 Python을 찾지 못한 것입니다. 기본 설치 경로를 확인하거나 위의 직접 설치 방법을 사용하세요. |
| 화면이 자동으로 열리지 않음 | 오류가 없다면 `data/server.port`의 숫자를 확인하고 브라우저에서 `http://127.0.0.1:해당숫자`를 엽니다. 기본 주소는 `http://127.0.0.1:8765`입니다. 시작 스크립트는 8765~8775에서 사용할 포트를 찾습니다. |
| 영상이 재생되지 않음 | **프레임 모드**로 전환하세요. 소리 없이 장면별 이미지로 검토합니다. 이 모드에서도 읽히지 않으면 H.264 MP4로 변환한 파일을 사용하세요. |
| `models/yolo11n.pt가 없습니다` 오류가 나옴 | `setup.ps1`로 모델을 준비하거나 위의 직접 설치 방법에 따라 모델 파일을 저장하세요. |
| 분석이 느림 | 짧은 구간과 기본 5fps로 시작하세요. 현재 분석 코드는 CPU로 모델을 실행합니다. 동시에 분석할 수 있는 영상은 하나입니다. |
| 분석했는데 점수가 0임 | 자동 후보는 아직 집계되지 않습니다. 선수·슛 결과·점수 구분을 확인하고 **확정하고 기록**을 눌렀는지 확인하세요. |
| 슛 후보나 선수 연결이 부정확함 | 전신 참고 장면과 골대 적용 구간을 확인합니다. 누락된 장면은 수동으로 기록하고 잘못된 후보는 제외하세요. |
| 분석 오류의 원인을 확인하고 싶음 | 해당 영상 폴더의 `last_error.log`를 확인합니다. 서버 시작 오류는 `data/server.log`, 일반 출력은 `data/server-output.log`에 남습니다. |

브라우저 창은 한 개에서 작업하는 것을 권장합니다. 오류 때문에 자동 분석을 완료하지 못해도 수동 기록은 계속 사용할 수 있습니다.

## 7. 코드를 처음 읽는 개발자를 위한 안내

이 프로젝트는 **파이썬 기초 문법만으로 모든 코드를 이해할 수 있는 난이도는 아닙니다.** 반복문과 딕셔너리로 이해할 수 있는 기록 집계부터, 웹 서버와 영상 추적처럼 추가 학습이 필요한 부분까지 섞여 있습니다.

### 파일별 역할과 읽는 순서

| 순서 | 파일 | 역할과 필요한 지식 |
| --- | --- | --- |
| 1 | [stats.py](stats.py) | 기록의 입력값을 검사하고 선수별 합계를 계산합니다. 함수, 리스트, 딕셔너리, 조건문·반복문을 중심으로 읽을 수 있도록 작성했습니다. |
| 2 | [tests/test_records.py](tests/test_records.py) | 어떤 기록을 합산하는지 작은 예제로 보여줍니다. `unittest`의 기본 사용법을 알면 집계 규칙을 확인하기 좋습니다. |
| 3 | [server.py](server.py) | 화면의 요청을 받아 영상·선수·기록을 저장하고 분석을 시작합니다. FastAPI, HTTP 요청, 예외 처리, 파일 입출력, 스레드 개념이 필요합니다. |
| 4 | [analysis.py](analysis.py) | 영상에서 사람·공을 찾고 추적 구간과 슛 후보를 만듭니다. OpenCV, NumPy 배열, 이미지 좌표·색상 비교, 객체 추적 알고리즘 학습이 필요합니다. |
| 5 | [static/index.html](static/index.html), [static/style.css](static/style.css), [static/app.js](static/app.js) | 화면 구조·디자인·버튼 동작을 담당합니다. Python과 별도로 HTML·CSS·JavaScript를 사용하며, `app.js`는 비동기 요청과 화면 상태 관리도 다룹니다. |
| 참고 | `setup.ps1`, `start.ps1`, `stop.ps1` | 설치·시작·종료를 돕는 PowerShell 스크립트입니다. `start.cmd`, `stop.cmd`는 더블클릭용 실행 파일입니다. |
| 참고 | `requirements.txt`, `requirements-dev.txt` | 프로그램 실행용 라이브러리와 테스트용 추가 라이브러리 목록입니다. |
| 참고 | [VALIDATION.md](VALIDATION.md), `tests/` | 기존 검증 기록과 자동 테스트입니다. 검증 범위와 한계를 확인할 수 있습니다. |

### 버튼을 누르면 코드가 어떻게 이어지나요?

예를 들어 슛 기록을 확정할 때는 다음 순서로 동작합니다.

1. `static/app.js`가 화면에서 입력한 선수·슛 결과·점수·확정 상태를 서버에 보냅니다.
2. `server.py`의 `event_add()` 또는 `event_update()`가 요청을 받습니다.
3. `stats.py`의 `validate_event()`가 선수가 등록되어 있는지, 확정에 필요한 값이 있는지 검사합니다.
4. `server.py`의 `save_session()`이 영상별 `session.json`에 기록을 저장합니다.
5. 응답을 만들 때 `stats.py`의 `boxscore()`가 확정된 기록만 다시 합산하고, 화면이 결과를 표시합니다.

자동 분석에서는 `server.py`의 `analyze()` → `worker()` → `analysis.py`의 `run_analysis()` 순서로 실행됩니다. 분석은 화면 요청 처리를 오래 막지 않도록 별도 작업 스레드에서 진행합니다.

`analysis.py`를 읽을 때 `box`는 보통 `[왼쪽, 위쪽, 오른쪽, 아래쪽]` 좌표이며, 각 값은 영상 크기를 기준으로 한 0~1 사이의 비율입니다. 예를 들어 가로 위치 0.5는 영상의 가로 중앙입니다. `track_id`는 잠깐 이어지는 추적 구간의 번호이고, 등록한 선수의 `player_id`와는 다릅니다.

핵심 파이썬 코드는 역할이 드러나는 변수명, 단계별 조건문·반복문, 한국어 함수 설명을 사용하도록 정리했습니다. `server.py`의 `sid`·`pid` 같은 API 주소 매개변수는 기존 호출을 유지하기 위해 남겨 두었으며 파일 첫 부분에 뜻을 설명했습니다.

서버의 `merge_analysis()`는 재분석 구간을 교체하고, `replace_pending_candidates()`는 기존 기록을 보존하면서 자동 미확정 후보를 갱신합니다. 영상 분석의 `suggest_shooter()`는 공과 선수의 위치를 비교해 슈터 후보를 제안합니다. 각 함수의 입력과 처리 순서를 먼저 따라가세요.

영상 처리 알고리즘 자체에는 추가 학습이 필요합니다. 특히 `Tracker`의 일대일 대상 연결, `HoopLocator`의 골대 이미지 비교, NumPy 이미지 배열은 파이썬 문법 외의 개념입니다. 코드의 비교 비중과 판단 수치는 기존 동작을 유지한 기준이며 측정된 정확도를 뜻하지 않습니다. 화면 코드인 `static/app.js`에는 별도로 JavaScript 학습이 필요합니다.

### 테스트 실행하기

설치가 끝난 프로젝트 폴더에서 PowerShell을 열어 실행합니다. `.venv`의 Python 경로를 직접 사용하므로 별도의 가상환경 활성화 명령은 필요하지 않습니다.

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

테스트는 기록 집계, 영상 업로드·수정 API, 색상 비교와 추적 등 일부 동작을 확인합니다. 실제 경기의 슛 검출 정확도를 측정하는 테스트는 아니며, 기존 검증 내용은 [VALIDATION.md](VALIDATION.md)를 참고하세요.
